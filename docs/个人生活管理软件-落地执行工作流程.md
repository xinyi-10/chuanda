> 主线顺序：**数据库搭建 → 项目框架搭建 → 编码实现 → 测试与验收**
> 角色：xinyi（开发者/全栈）· 灵犀（AI 协作/评审）

## 〇、流程总览与全局约定

### 0.1 主线四阶段

```
阶段一：数据库搭建 ──► 阶段二：项目框架搭建 ──► 阶段三：编码实现 ──► 阶段四：测试与验收
        (前置地基)          (工程骨架)              (业务落地)            (质量闭环)
```

### 0.2 并行 / 串行总览

| 关系 | 步骤 |
|---|---|
| **严格串行**（必须等前置完成） | 阶段一 → 阶段二 → 阶段三 → 阶段四 依次推进；阶段三内部按「鉴权 → 笔记 → 记账 → 穿搭」顺序 |
| **可并行** | 阶段一内部：各建表脚本可同时写；阶段二内部：后端工程与前端工程可并行搭建；阶段三：后端接口与前端页面在「接口契约」锁死后可并行开发 |
| **触发条件** | 每个阶段以「验收标准全部通过」为进入下一阶段的唯一开关 |

### 0.3 贯穿全程的三件 P0 铁律（来自审核报告）

无论走到哪一阶段，以下三件事**必须从阶段二起就钉死**，不允许后补：

1. **数据隔离**：所有涉及用户数据的 SQL 强制带 `user_id`（阶段二用 MyBatis 拦截器统一注入，见 2.4）。
2. **金额精度**：金额字段 `DECIMAL(12,2)` + Java `BigDecimal` + JSON 序列化为字符串，三处一致。
3. **异步超时补偿**：`@Async` 任务必须配超时检测 + 状态机终态，不允许「永久执行中」。

## 阶段一：数据库搭建（地基）

> **目标**：产出可执行的建表脚本，字段/索引/约束与方案一致，且已吸收审核报告的数据一致性改进（H6/M8/L4/L5）。

### 1.1 执行步骤

| 步骤 | 关键动作 | 依赖 | 风险点 |
|---|---|---|---|
| 1.1 确认数据库环境 | 安装/连接 MySQL 8.0，确认 `utf8mb4` 字符集、可创建用户与库 | 无 | 版本 <8.0 不支持窗口函数（影响统计）；字符集误用 utf8 导致 emoji 乱码 |
| 1.2 编写 `schema.sql` | 建库 + 全部表 + 索引 + 约束 | 1.1 | 见下方「字段级修正」清单，漏改会导致后期返工 |
| 1.3 编写 `data.sql`（种子数据） | 预置默认分类（餐饮/交通/工资…）、衣物标签字典 | 1.2 | 分类枚举自由文本（L5）导致规则引擎匹配失效 |
| 1.4 本地执行验证 | 执行脚本，`SHOW CREATE TABLE` 核对字段/索引 | 1.3 | 直接改已上线库、无备份 |
| 1.5 记录数据库版本 | 建表脚本纳入 Git，编号（如 `V1__init.sql`） | 1.4 | 后续变更无版本管理，多人协作冲突 |

### 1.2 必须吸收的审核改进点（建表时直接落实）

| 编号 | 问题 | 落地做法 |
|---|---|---|
| H6 | `type` 双重冗余 | 流水表 `ledger_record` 只保留 `category_id`，`type` 由分类派生；应用层校验一致性 |
| M8 | 逻辑删除 + 唯一约束缺失 | 分类名唯一索引用 `user_id + name + deleted` 复合索引 |
| L4 | 异步任务状态机不完整 | `async_task.status` 增加终态：`4=超时` `5=取消`；补 `timeout_at` 字段 |
| L5 | 枚举用 VARCHAR 存自由文本 | `season/style/category` 建字典表或加 `CHECK` 约束，杜绝「夏/夏季」不一致 |
| H5 | 金额序列化 | 表字段 `DECIMAL(12,2)`（库层）——Java/JSON 层在阶段二处理 |

### 1.3 验收标准（阶段一出口门禁）

- [ ] `schema.sql` 可在干净 MySQL 8.0 上一次性执行成功，无报错。
- [ ] 所有表含 `user_id / create_time / update_time / deleted` 通用字段。
- [ ] 金额字段均为 `DECIMAL(12,2)`，无 `FLOAT/DOUBLE`。
- [ ] H6/M8/L4/L5 四项修正已体现在脚本中。
- [ ] 种子数据可正常导入，默认分类可直接被前端渲染。

**→ 衔接**：验收通过后，产出 `sql/schema.sql` + `sql/data.sql` 两个文件，作为阶段二的数据库连接依据。

## 阶段二：项目框架搭建（工程骨架）

> **目标**：跑通一个「能启动、能连库、能鉴权、统一响应」的空壳，并把三件 P0 铁律的基建全部铺好。

### 2.1 执行步骤（后端 + 前端可并行）

| 步骤 | 关键动作 | 依赖 | 风险点 |
|---|---|---|---|
| 2.1 初始化后端工程 | SSM（Maven/WAR）工程骨架，`applicationContext.xml` + `spring-mvc.xml` + `pom.xml` | 1.x 通过 | 见「JDK 隐患」 |
| 2.2 初始化前端工程 | Vue3 + Vite + Element Plus + Pinia + Axios | 1.x 通过 | Element UI/Vue3 版本冲突（已纠正为 Element Plus） |
| 2.3 配置数据库连接 | HikariCP/Druid 连接池接入，`mapUnderscoreToCamelCase=true` | 1.5 + 2.1 | 连接池参数不合理（maximumPoolSize） |
| 2.4 **铺设 P0 基建** | 数据隔离拦截器 + BigDecimal 序列化 + 统一响应 `Result` + 全局异常 | 2.1 | 见下方「P0 基建清单」 |
| 2.5 鉴权链路 | 登录/注册 + JWT 签发 + 拦截器校验 | 2.4 | H1 token 机制含糊，需此时定死 |
| 2.6 异步框架 | `@EnableAsync` + `outfitExecutor` 线程池 + 超时补偿定时任务 | 2.4 | H4 超时检测此时必须搭好，不能等业务才补 |
| 2.7 接口契约 | Knife4j/springdoc 或 Apifox 锁定首批接口文档 | 2.5 | M5 swagger 兼容坑 |
| 2.8 联调打通 | 前端登录 → 后端接口 → 数据库全链路跑通 | 2.1~2.7 | 跨域配置（L2） |

### 2.2 P0 基建清单（阶段二必须完成，不后移）

| 基建 | 对应风险 | 关键实现 |
|---|---|---|
| 数据隔离拦截器 | H2 | MyBatis 拦截器自动给「含 user_id 的表」注入 `user_id` 条件，越权=漏写直接拦截 |
| BigDecimal 序列化 | H5 | Jackson 全局配置 `BigDecimal` 输出字符串；金额出参禁用 double |
| 统一响应 + 错误码 | M4/M7 | 定义 `code/msg/data/timestamp`，`timestamp` 后端生成；建立错误码枚举 |
| 超时补偿任务 | H4 | 定时扫描 `status=1 且 now>timeout_at` 的任务 → 置为「超时」终态 |
| Token 双机制 | H1 | access token（短期）+ refresh token，明确存储位置与刷新流程 |

### 2.3 关键环境隐患（JDK）

- **风险**：IntelliJ IDEA 可能静默用 JDK 23 跑 Maven，而项目配的是 JDK 17，引发运行期异常。
- **动作**：阶段二启动时，先核对 `pom.xml` 的 `maven.compiler` 与 IDEA 的 Project SDK、Maven runner 三项一致为 JDK 17，并写进团队备忘。

### 2.4 验收标准（阶段二出口门禁）

- [ ] 后端 `mvn package` 成功产出 `property-management.war`，Tomcat/Jetty 可启动。
- [ ] 前端 `npm run dev` 可启动，页面正常渲染。
- [ ] 登录 → 签发 token → 访问受保护接口全链路通。
- [ ] 数据隔离拦截器生效（用一个「不带 user_id」的越权请求验证会被拦）。
- [ ] 金额接口返回字符串（非浮点）。
- [ ] 异步任务超时补偿定时任务已注册并可用。

**→ 衔接**：产出可运行空壳 + 接口契约文档，作为阶段三并行开发的「共同基准」。

## 阶段三：编码实现（业务落地）

> **目标**：按「鉴权 → 笔记 → 记账 → 穿搭」顺序实现业务，前后端在接口契约锁死后并行开发。

### 3.1 模块执行顺序与依赖

```
3.1 鉴权加固 ──► 3.2 笔记模块 ──► 3.3 记账模块 ──► 3.4 穿搭模块 ──► 3.5 前端页面联调
```

| 步骤 | 关键动作 | 依赖 | 风险点 |
|---|---|---|---|
| 3.1 鉴权加固 | token 刷新/登出失效完整流程 | 2.5 | H1 若无 refresh 则体验差 |
| 3.2 笔记模块 | CRUD + 分类 + 搜索 | 2.4 + 2.7 | M1 搜索 `LIKE '%kw%'` 性能 |
| 3.3 记账模块 | 流水 CRUD + 统计（总览/分类/趋势） | 3.2（复用数据隔离） | H6 type 一致性校验 |
| 3.4 穿搭模块 | 衣物库 + 天气接入 + LLM 接入 + 异步链路 + 兜底 | 2.6 + 3.3 | H3 prompt 注入 / M6 熔断限流 |
| 3.5 前端页面 | 各模块 Vue 页面 + Pinia + 图表 | 对应后端接口 | M2 轮询压力 |

### 3.2 编码期必须落实的审核改进点

| 编号 | 问题 | 落地做法 |
|---|---|---|
| H3 | Prompt 注入 | 衣物名/备注拼入 LLM prompt 前做转义/角色隔离；LLM 输出只取结构化衣物 ID |
| M6 | 外部依赖无熔断限流 | 天气/LLM 各配独立线程池 + 信号量限流 + 超时 + 重试（≤2 次）+ 熔断 |
| M1 | 搜索性能 | 明确数据量阈值；超过即切 FULLTEXT（`ngram` parser）；加最小搜索长度 |
| M3 | 衣物删除后历史「死 ID」 | `items_json` 存快照（id+name+category 冗余） |
| M2 | 轮询压力 | 前端轮询加指数退避；结果查询走缓存，避免每 1s 打 DB |
| M5 | Swagger 兼容 | 用 springdoc-openapi 或 Apifox 维护契约 |

### 3.3 并行 / 串行说明

- **可并行**：3.2 笔记、3.3 记账的前端页面可与后端接口并行（契约已锁）。
- **必须串行**：3.4 穿搭依赖 2.6 异步框架 + 3.3 的数据隔离经验；3.3 记账依赖 3.2 笔记验证过的数据隔离链路。

### 3.4 验收标准（阶段三出口门禁）

- [ ] 每个模块 CRUD + 查询接口联调通过，统一响应格式正确。
- [ ] 数据隔离在所有新接口生效（越权测试通过）。
- [ ] 金额计算/统计结果精度正确（BigDecimal 全程）。
- [ ] 穿搭推荐异步链路跑通：正常路径 + LLM 失败兜底（source=2）+ 超时补偿。
- [ ] 前端页面可完整操作，无阻塞性 bug。

**→ 衔接**：产出完整业务代码，进入阶段四测试与验收。

## 阶段四：测试与验收（质量闭环）

> **目标**：用测试覆盖审核报告中缺失的测试策略（L1），并完成安全/性能/一致性专项验收。

### 4.1 执行步骤

| 步骤 | 关键动作 | 依赖 | 风险点 |
|---|---|---|---|
| 4.1 单元测试 | 金额计算、规则引擎兜底、type 校验 | 3.x | 金额用 double 断言 |
| 4.2 集成测试 | 异步链路状态机、登录鉴权全流程 | 4.1 | 异步测试时序不稳定 |
| 4.3 安全专项 | 越权、XSS、prompt 注入、CORS | 3.x | 越权漏测（最高风险） |
| 4.4 性能专项 | 深分页、搜索大表、轮询压力 | 3.x | 深分页 `LIMIT 100000,10` |
| 4.5 验收 + 部署 | Nginx + Tomcat 部署，上线清单核对 | 4.1~4.4 | L3 多实例与缓存一致性 |

### 4.2 必测清单（对应审核 L1）

| 必测项 | 对应风险 |
|---|---|
| 金额计算 / 统计聚合 | H5、L6 |
| 规则引擎兜底逻辑 | H4 降级 |
| 越权访问（跨用户读数据） | H2 |
| 异步任务状态机（成功/失败/超时/取消） | H4、L4 |
| 逻辑删除后同名分类重建 | M8 |

### 4.3 验收标准（阶段四出口门禁）

- [ ] 单元测试 + 集成测试全部通过。
- [ ] 越权专项测试通过（无跨用户数据泄露）。
- [ ] 金额全程精度正确，统计 percent 总和为 100%。
- [ ] 异步任务无「永久执行中」残留。
- [ ] 部署后 Nginx 反向代理 `/api` 正常，生产无 CORS 问题。
