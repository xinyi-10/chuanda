Navicat 数据导入与校验
操作指南

首选「SQL 转储 → 运行 SQL 文件」，次选「数据传输」，表数据零散时才用 CSV / Excel。 目标库 life_manager（MySQL 8 · utf8mb4）。

1先明确三件事

项说明
目标库life_manager（若改名，同步改导入语句与连接配置）
目标字符集必须 utf8mb4，否则中文 / emoji 乱码（最高频的坑）
目标表结构以 sql/schema.sql 为准；源字段不一致时先做字段映射

3三条导入路径（按数据形态选一条）

路径 A · SQL 转储导入

结构 + 数据最稳，推荐

右键 → 转储 SQL 文件运行 SQL 文件

路径 B · 数据传输

源/目标都能在 Navicat 连上时用

工具 → 数据传输数据同步

路径 C · CSV / Excel 导入

只有单表表格数据时用

右键 → 导入向导字段映射

路径 A 步骤（推荐）

  1. 源连接 → 右键库/表 → 转储 SQL 文件 → 选 结构和数据
  2. 保存 .sql，编码选 UTF-8
  3. 目标连接 life_manager → 右键 → 运行 SQL 文件 → 选文件 → 执行
# 等价命令行（更快）
mysql -h 127.0.0.1 -P 3306 -u root -p life_manager < "D:/path/to/dump.sql"

路径 B 步骤

  1. 工具 → 数据传输
  2. 选源连接+库 → 选目标连接+库
  3. 勾选表；高级选项可设「遇错继续 / 遇重复跳过」
  4. 点 开始；增量场景用 数据同步 / 结构同步 先比对再同步

路径 C 步骤

  1. 准备文件：首行列名、UTF-8 编码
  2. 目标表右键 → 导入向导 → 选 csv / xlsx
  3. 设置分隔符、首行作为字段名、编码 UTF-8
  4. 字段映射逐列核对（最易错的一步）
  5. 导入模式：追加 / 更新 / 覆盖 → 开始

4导入后校验（6 步闭环）

  • ① 结构校验
    SHOW TABLES; 应为 9 张；SHOW CREATE TABLE ledger_record\G 核对字段/类型/索引
  • ② 行数比对
    SELECT COUNT(*) 源 ↔ 目标逐表对；或用 Navicat 工具 → 表数据对比
  • ③ 编码校验
    SHOW VARIABLES LIKE 'character_set_database'; 应为 utf8mb4；抽中文样本查
  • ④ 业务完整性
    查孤儿数据（分类被引用但不存在）、金额汇总比对、必填字段非空
  • ⑤ 抽样人工比对
    SELECT * FROM ledger_record ORDER BY RAND() LIMIT 10; 逐字段核对
  • ⑥ 应用层验证
    启动 SSM，调 /api/ledger/stat/overview，返回值与 SQL 汇总一致即打通

校验 SQL 片段

USE life_manager;

-- 行数盘点
SELECT 'note' AS tbl, COUNT(*) cnt FROM note
UNION ALL SELECT 'ledger_record', COUNT(*) FROM ledger_record
UNION ALL SELECT 'clothing_item', COUNT(*) FROM clothing_item;

-- 孤儿数据（引用了不存在的分类）
SELECT COUNT(*) FROM note n
  LEFT JOIN note_category c ON n.category_id = c.id
  WHERE n.category_id IS NOT NULL AND c.id IS NULL AND n.deleted = 0;

5常见坑与对策

#坑现象对策
1字符集不对中文/emoji 乱码或 ???建库 utf8mb4；导出导入都选 UTF-8
2日期格式歧义2/4/2026 解析错导入时指定 yyyy-MM-dd HH:mm:ss
3主键冲突Duplicate entry目标先 TRUNCATE，或导出时去掉自增 id
4金额失真0.1 变 0.0999999目标列 DECIMAL，源数据避免浮点
5LOAD DATA 被拒ERROR 1290 secure_file_priv用 LOCAL INFILE 或改 MySQL 配置
6时区偏移时间差 8 小时连接串加 serverTimezone=Asia/Shanghai
7自增 ID 跳号id 不连续正常现象，不影响

6给你的最短路径

# ① 建库建表
mysql -u root -p < "D:/AI/workbuddy/ChuanDa/sql/schema.sql"
# ② 种子数据（字典 + 默认分类）
mysql -u root -p life_manager < "D:/AI/workbuddy/ChuanDa/sql/data.sql"
# ③ 你的 Navicat 数据（先转储为 sql，再执行）
mysql -u root -p life_manager < "D:/path/to/navicat_dump.sql"
# ④ 校验
mysql -u root -p life_manager -e "SELECT COUNT(*) FROM ledger_record;"
i

顺序很重要：先结构（schema）→ 再种子（data）→ 最后业务数据，避免外键/分类引用对不上。
